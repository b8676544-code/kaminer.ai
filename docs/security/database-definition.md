# מסמך הגדרות מאגר — kaminer.ai

> **LAW-1 ו-LAW-4:** לפי תקנה 2 לתקנות הגנת הפרטיות (אבטחת מידע), התשע"ז-2017, למאגר שמנוהל בידי יחיד.
> **עדכון אחרון:** 24.11.2026. מעדכנים כשמשתנה מטרה, סוג מידע, ספק או מקום אחסון, ולפחות פעם בשנה.
> **זה לא ייעוץ משפטי.** הסעיפים המסומנים "פתוח" מחכים להחלטה. לפני שעוברים לענן כדאי לעבור על המסמך עם עו"ד.

## 1. פרטי המאגר
- **שם:** מערכת ניהול משימות kaminer.ai.
- **בעלת המאגר ומחזיקתו:** בעלת העסק, משתמשת יחידה.
- **מורשי גישה:** בעלת העסק בלבד. לפרילנסרים אין התחברות, הם רשומות במאגר בלבד.
  - **פתוח:** אם בעתיד פרילנסרים יקבלו התחברות, צריך לעדכן את המסמך ולבדוק מחדש את רמת האבטחה.
- **מיקום:** מקומי, במחשב העסק (Supabase ב-Docker). אחרי המעבר לענן: ראו סעיף 5.

## 2. מטרות השימוש
- ניהול לקוחות, אנשי קשר ופרויקטים.
- ניהול משימות, כולל שיוך לפרילנסרים ותמחור.
- יומן פגישות וסנכרון עם Google Calendar של בעלת העסק.
- מדידת זמן עבודה וחישוב חיובים.
- משימות ופגישות אישיות של בעלת העסק, גלויות רק לה.

אין שימוש במידע לדיוור, לפרסום, למכירה או לפרופיילינג. אין העברה לצד שלישי מלבד הספקים בסעיף 5.

| טבלה | מה נשמר | רגישות |
|---|---|---|

| `client_contacts` | שם, תפקיד, טלפון ומייל של אנשי קשר אצל הלקוח | רגיל |
| `freelancers` | שם, תחום, טלפון, מייל, עלות לשעה, הערות | מידע כלכלי על אדם |
| `projects` | שם, תיאור, תאריכים, מחיר | עסקי |
| `tasks`, `task_checklist_items`, `task_notes`, `task_templates` | משימות, תתי־משימות, הערות, תבניות. משימות אישיות פרטיות | משימות אישיות עלולות להכיל מידע אישי |

## 4. אמצעי אבטחה
- **התחברות:** Supabase Auth, עם סיסמה או קישור במייל. אין הרשמה פתוחה.
  - **פתוח:** אימות דו־שלבי (MFA), ב-todo.md.
- **הרשאות בבסיס הנתונים:**
  - RLS על כל טבלה: כל רשומה שייכת ל-`owner_id`, ורק הבעלים רואה ומשנה.
  - למשתמש אנונימי אין הרשאות בכלל (מיגרציה `20261128120000_tighten_grants.sql`).
- **סודות:** רק ב-`.env`, שלא נכנס ל-git. מפתח השירות (service role) משמש רק בשרת.
- **תעבורה:** כותרות אבטחה ב-`next.config.ts`. HTTPS מופעל ב-Deploy.
- **גיבוי:** מוצפן, ראו סעיף 7.
- **המחשב המקומי:** הצפנת דיסק (BitLocker) ונעילת מסך.
  - **פתוח:** לוודא ש-BitLocker מופעל (`manage-bde -status`, בהרשאת מנהל).

## 5. ספקים, מדינות ובסיס להעברה לחו"ל (LAW-4)
מעבירים מידע לספק בחו"ל רק כשהספק התחייב בכתב לשמור עליו (תקנות הגנת הפרטיות, העברת מידע למאגרי מידע שמחוץ לגבולות המדינה, התשס"א-2001). ההתחייבות היא הסכם עיבוד הנתונים (DPA) של הספק. מדינות האיחוד האירופי חלות עליהן הגנה דומה, ולכן מעדיפים אזור אירופי.

| ספק | מה עובר | מדינה | בסיס | מצב |
|---|---|---|---|---|
| Google (Calendar API) | פגישות: כותרת, זמנים, מקום, הערות, מוזמנים | ארה"ב ואחרות | Workspace: ‏[Cloud Data Processing Addendum](https://workspace.google.com/terms/dpa_terms.html). ‏Gmail פרטי: אין DPA, רק תנאי השימוש | **פתוח:** Workspace או Gmail |
| Resend (מייל התראה) | מייל התראה על כשל סנכרון, לבעלת העסק בלבד | ארה"ב | [DPA](https://resend.com/legal/dpa) | פעיל רק כשמוגדר המפתח |
| GitHub | קוד המערכת, וגיבוי מוצפן של ה-DB (אחרי E3) | ארה"ב | [Data Protection Agreement](https://github.com/customer-terms) | **פתוח:** לוודא שהריפו פרטי |
| Supabase (אחרי E3) | כל המאגר | אזור EU (פרנקפורט) | [DPA](https://supabase.com/legal/dpa) | עתידי |
| Vercel (אחרי E3) | הקוד, ובקשות שעוברות דרך השרת | אזור fra1 (פרנקפורט) | [DPA](https://vercel.com/legal/dpa) | עתידי |

את הקישורים כדאי לבדוק כשמחליטים, כי הספקים מעדכנים אותם.

**לשים לב, ממצא LAW-2 (ב-todo.md):** פגישה עם מוזמנים נשלחת אליהם דרך Google, כולל ההערות והמקום. לא לכתוב בהערות של פגישה עם מוזמנים דברים שלא מיועדים להם.

## 7. גיבוי ושחזור
- **מקומי:** `npm run db:backup` (`scripts/backup-local.mjs`).
  - **מה נשמר:** הסכמות public ו-auth, מוצפנות ב-AES-256-GCM.
  - **איפה:** `LOCAL_BACKUP_DIR`, או `kaminer-backups` בתיקיית המשתמש. כדאי שהתיקייה תסונכרן לאחסון חיצוני (למשל OneDrive), כי הקובץ מוצפן.
  - **כמה זמן:** 30 יום.
  - **הסיסמה:** `LOCAL_BACKUP_PASSPHRASE` ב-`.env`. לשמור עותק גם מחוץ למחשב.
- **שחזור מקומי:**
  1. `node scripts/backup-local.mjs --decrypt <קובץ.kmb> restore.dump`
  2. `docker cp restore.dump supabase_db_kaminer-ai:/tmp/restore.dump`
  3. `docker exec supabase_db_kaminer-ai pg_restore -U postgres -d postgres --clean --if-exists /tmp/restore.dump`
  4. למחוק את `restore.dump`, שאינו מוצפן.
- **בענן (אחרי E3):** `.github/workflows/db-backup.yml`. השחזור מתואר ב-`docs/PRD.md` §9.5.
