# מבנה האפליקציה — 18.11.2026

**הקשר:** משימה S2b, אחרי אישור ה-PRD. הוקם שלד Next.js + Supabase בלי פיצ'רים.

**החלטות:**
1. **Next.js 16 עם App Router ו-`src/`.** ה-route groups מפרידים בין `(auth)` הציבורי ל-`(app)` המוגן. ההגנה תהיה ב-`proxy.ts`, שמחליף את `middleware.ts` ב-Next 16.
2. **`src/features/<domain>/`** מחזיקה את הלוגיקה של כל תחום (Server Actions, שאילתות, סכמות zod), ו-`app/` נשאר רק ניתוב.
3. **ה-DB מנוהל רק דרך `supabase/migrations`.** הטיפוסים נוצרים ב-`npm run db:types`, והמעבר לענן הוא `supabase db push`.
4. **סנכרון Google רץ ב-API routes** (`api/google/oauth`, ‏`api/google/sync`), כי ה-refresh token לא יוצא מהשרת לעולם.
5. **Supabase CLI מותקן כ-devDependency** ולא גלובלית, כדי שהגרסה תהיה נעולה לפרויקט.
6. **רכיבי shadcn נכתבו ידנית.** ‏`ui.shadcn.com` חסום ברשת המקומית; התלויות הותקנו מ-npm.

**חלופות שנדחו:**
- Server Actions בתוך תיקיות ה-routes: מפזר את לוגיקת התחום בין מסכים.
- Edge Functions לסנכרון Google: מיותר בריצה מקומית; API routes של Next מספיקים, ויעברו ל-Vercel בלי שינוי.

**פתוח:** Docker Desktop לא מותקן, ולכן `npm run db:start` עוד לא נבדק.
